## 확정 로드맵. GEOFlow → Blogger 자동 발행 연동 (방식 B, 직접 발행)

### 확정 사항 (2026-07-24, 최종 정정)
- 실제 발행 대상 블로그: **https://daesan-inside.blogspot.com/**
- 파이프라인 방향: **GEOFlow가 글을 생성 → GEOFlow가 Blogger API로 직접 발행**
- 기존 Google Apps Script + Sheets 자동화(01/05/06/08번 문서)는 **이 프로젝트와 무관함**. 그 시스템은 사용하지 않으며, 아래 항목은 순수 참고용으로만 반영했음:
  - 문체/스타일 규칙 (도입 후킹, 조직형 화법, 자문자답 등) → 이미 한국어 GEO 프롬프트에 반영 완료
  - "고정요소(CTA·서명·뱃지)는 AI 프롬프트가 아니라 코드가 발행 시점에 붙인다"는 아키텍처 아이디어 → GEOFlow 자체 Blogger 발행 기능을 만들 때 동일하게 적용 예정
- 즉 아래 "검토 배경"의 **방식 A는 채택하지 않음** (Drive 업로드 → 기존 Apps Script 경유 방식은 안 함)

### 만들어야 할 것 (아직 미착수, 확정 로드맵)
1. **Blogger 발행 기능을 GEOFlow 코드에 신규 구현**
   - `app/Services/GeoFlow/DistributionPublisherInterface.php`를 구현하는 `BloggerPublisher.php` 신규 작성
   - `app/Services/GeoFlow/DistributionPublisherManager.php`의 매핑 배열에 `'blogger' => $this->bloggerPublisher` 추가
   - Blogger API 인증(OAuth) 처리 필요
2. **고정요소(신뢰뱃지·CTA·서명) 삽입 코드 함께 구현**
   - 오늘 설계했던 `insertFixedElements()` / `insertTrustBadge()` / `insertCta()` / `appendSignature()` 함수를 이때 `WorkerExecutionService.php`에 정식 추가
   - CTA 링크: `https://web-cadalog-ver10.vercel.app/`
   - 뱃지 이미지: Image Library에 업로드 후 실제 URL로 교체 (현재 `TRUST_BADGE_URL_PLACEHOLDER` 상태)
   - **주의**: 1번(Blogger 발행 기능)과 반드시 같이 만들 것. 발행 기능 없이 이 코드만 먼저 넣으면 GEOFlow 로컬 글에도 CTA/뱃지가 붙어버려서, 나중에 Blogger에 옮겨질 때 다른 경로로 중복 삽입될 위험이 있음 (지금은 둘 다 미적용 상태로 유지)

### 지금 당장(오늘)의 운영 방식
- GEOFlow는 본문(제목+내용+비교표+FAQ)만 생성, 검수까지 진행
- 실제 Blogger 발행은 위 로드맵 완성 전까지 사람이 수동으로 처리 (복사해서 Blogger 편집기에 직접 붙여넣기)

## 검토 배경 (참고용, 채택 안 함) - Blogger 자동 발행 기능 검토 과정

### 지금 상황
GEOFlow는 코드 확인 결과 아래 3가지 발행 방식만 지원합니다.
- `geoflow_agent`
- `wordpress_rest`
- `generic_http_api`

Blogger 발행 기능은 코드 전체를 검색해도 존재하지 않습니다 (`grep -i blogger` 결과 0건).

이미 별도로 운영 중인 **Google Apps Script + Google Sheets 기반 Blogger 자동화**가 있고,
이 시스템은 이미 완성되어 실제 운영 중입니다 (`01_시스템가이드.md`, `06_프롬프터최적화.md`, `05_이미지생성로직.md` 참고).

### 이 검토 당시 고려했던 것 (참고 기록)
처음에는 "GEOFlow와 기존 Blogger 자동화를 분리 운영"하는 방향(방식 A)을 검토했으나,
**최종적으로는 채택하지 않음**. 기존 Apps Script 시스템은 이 프로젝트의 발행 파이프라인으로 쓰지 않기로 확정.
문체 스타일과 "고정요소는 코드가 붙인다"는 아이디어만 참고 자료로 남기고, 실제 구현은 위 "확정 로드맵"(방식 B, GEOFlow가 Blogger API로 직접 발행)을 따름.

## 보류 항목 2. 이미지 자동 생성 기능

### 지금 상황
GEOFlow의 `ai_models` 테이블은 `model_type`이 `chat` 또는 `embedding`만 존재합니다.
이미지 생성 AI 모델을 등록하거나 호출하는 코드는 전혀 없습니다.

현재 GEOFlow가 이미지를 다루는 유일한 방법:
- Content Assets → Image Library에 **사람이 미리 업로드해둔 이미지**만 사용 가능
- Task 실행 시 `app/Services/GeoFlow/WorkerExecutionService.php`의 `insertTaskImagesIntoContent()` 함수가
  라이브러리에서 **무작위로** 이미지를 골라 문단 사이사이에 자동 삽입
- 즉 "이 글에 맞는 이미지를 새로 만들어주는" 기능이 아니라 "미리 준비된 사진첩에서 랜덤으로 꺼내 쓰는" 기능

### 참고할 기존 시스템 (Blogger 자동화)
`05_이미지생성로직.md`에 이미 정교한 설계가 있음:
- `image1`: 핵심 판단 구조를 보여주는 설명형 이미지 (Gemini + OpenAI 둘 다 생성 후 사람이 선택)
- `image2`: 비교표/체크리스트/매트릭스를 SVG로 만드는 보조 이미지
- 9가지 콘텐츠 유형별 `role_map` (자재비교, 시공실수, 성능설명, 구매가이드 등)
- `image2_table_data` 스키마: `columns`, `rows`, `legend`, `note`
- 검증 규칙: `rows` 4개 미만이면 재생성, role_map과 다르면 재시도

이 설계는 GEOFlow에 이미지 생성 기능을 만들 때 그대로 참고할 수 있는 좋은 뼈대입니다.
단, 통째로 이식하지 말고 필요한 부분만 가져올 것 (아래 단계별 참고).

### 왜 지금 안 만드나
- 아직 텍스트 파이프라인(제목 → 지식베이스 → 프롬프트 → 발행)조차 처음부터 끝까지 한 번 완주해보지 않은 상태
- 새 기능을 계속 쌓기 전에, 지금 있는 기능으로 결과물 품질부터 확인하는 게 우선
- 이미지 생성 API는 추가 비용 발생 (OpenAI/Gemini 이미지 생성은 텍스트보다 비쌈)

### 지금 당장의 대안 (코드 작업 없이 바로 가능)
1. MDF 실물 사진, 두께/밀도 비교표 이미지를 사람이 직접 준비
2. Content Assets → Image Library Management에 업로드
3. Task 생성 시 이 라이브러리를 Image Library로 지정, Image Count를 1~2로 설정
4. 완전 자동은 아니지만, 최소한 밋밋함은 해결됨

### 나중에 이미지 자동 생성을 만들 때 시작점

**1단계. AI 모델 종류에 'image' 타입 추가**
- 파일: `app/Models/AiModel.php`, `app/Http/Controllers/Admin/AiModelController.php`
- `model_type`에 `'image'`를 추가하고, 이미지 생성 모델(OpenAI DALL-E, Gemini Imagen 등)을 등록할 수 있게 확장

**2단계. 이미지 생성 서비스 신규 작성**
- 새 파일: `app/Services/GeoFlow/ImageGenerationService.php`
- 참고 대상: `05_이미지생성로직.md`의 `image1_role_map` (9개 유형)
- 처음에는 9개 유형 전부 말고, 1개 이미지(핵심 요약 이미지)부터 시작 권장

**3단계. WorkerExecutionService.php에 연결**
- `insertTaskImagesIntoContent()` 함수 근처에 새 함수 `generateAndInsertAiImage()` 추가
- Task에 "AI 이미지 자동 생성 사용 여부" 옵션 추가 (`tasks` 테이블에 컬럼 추가 필요, 마이그레이션 작성)

**4단계. SVG 비교표 이미지 (image2에 해당하는 기능)는 가장 나중에**
- `image2_table_data` 스키마처럼 구조화된 표 데이터를 SVG로 그려주는 기능은 난이도가 높음
- 1~3단계가 안정적으로 돌아간 뒤에 시도할 것
